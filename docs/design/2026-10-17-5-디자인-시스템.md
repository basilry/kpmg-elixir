## 1. 디자인 원칙

대상 사용자는 밀도 높은 데이터(전표, 룰 적중, AI 제안, 결론, 감사 로그)를 오래 보는 회계사/감사인이다. 톤은 차분하고 신뢰감 있게, 장식 없이 정보 중심으로 한다.

| # | 원칙 | 구체적 의미 |
|---|---|---|
| 1 | 밀도 우선 | 한 화면에 전표 행 15개 이상. 본문 14px, 컴팩트 테이블, 그림자 대신 1px 경계. 여백은 구분에만 쓴다. |
| 2 | 추적 가능성 | 모든 수치와 판단은 근거(전표, 룰, 로그)로 한 번에 이동한다. ID는 항상 mono로 전체 표기하고 자르지 않는다. 시각은 hover로 UTC 원본을 확인한다. |
| 3 | AI와 사람의 구분 | AI 산출물은 항상 보라색(accent) 점선 박스, "AI 제안" 라벨, 모델 ID를 갖는다. 사람 입력은 실선 박스다. AI가 사람의 입력란을 미리 채우지 않는다. |
| 4 | 상태 명료성 | 위험도, 작성자 판단, 검토 상태는 서로 다른 배지 모양(soft, outline, solid)과 아이콘을 쓴다. 모든 상태는 텍스트 라벨을 가진다. |
| 5 | 되돌릴 수 없는 행위는 분명하게 | 승인과 반려는 하단 sign-off bar에서만 한다. 직무분리로 막힌 이유는 비활성 버튼 옆에 텍스트로 보인다. 감사 로그에는 수정/삭제 UI가 없다. |
| 6 | 접근성은 기본값 | 색만으로 구분하지 않는다. 텍스트 대비 AA 이상. 키보드만으로 검토를 끝낼 수 있다. 라이트/다크가 같은 정보를 보여준다. |

### 2.2 결정: daisyUI를 프리미티브로 쓴다 (메인 세션 검토 후 채택)

refs/phoenix-guidelines.md는 "daisyUI 대신 직접 작성"을 권한다. 우리는 프리미티브(`btn`, `badge`, `input`, `select`, `textarea`, `table`, `progress`, `avatar`, `tabs`, `alert`, `skeleton`, `loading`, `tooltip`)만 daisyUI를 쓰고, 도메인 컴포넌트는 Tailwind 유틸리티로 조합한다.

- 이유: (1) 생성된 core_components가 이미 daisyUI에 의존한다. (2) 색 역할 토큰으로 라이트/다크가 자동 전환된다. (3) 1인 7일 일정.
- 트레이드오프: 기본 모양이 흔하다. 색, 반경, 깊이, 밀도 규칙(3장)으로 차별화한다.
- 지킬 규칙: `@apply` 금지, 외부 폰트/스크립트 링크 금지(app.css, app.js 번들만), 색은 역할 클래스(`bg-base-100`, `text-error`)로 쓰고 `dark:` 변형은 예외에만 쓴다.

### 3.2 도메인 의미 매핑 (3계열 배지는 모양이 다르다)

| 의미 | 라벨 | 색 역할 | 배지 스타일 | 아이콘 (hero-) |
|---|---|---|---|---|
| 위험도 높음 | 높음 | error | `badge-soft` | exclamation-triangle |
| 위험도 중간 | 중간 | warning | `badge-soft` | exclamation-circle |
| 위험도 낮음 | 낮음 | neutral | `badge-soft` | minus-circle |
| AI 미요청 / 분석 중 / 실패 (`triage_status` none / queued / failed) | -, 분석 중, AI 실패 | neutral, accent, error | 텍스트, `loading-dots` + 텍스트, `badge-ghost` + 텍스트 | -, -, exclamation-circle |
| 판단 이상 없음 (`no_exception`) | 이상 없음 | success | `badge-outline` | check-circle |
| 판단 추가 확인 필요 (`needs_follow_up`) | 추가 확인 필요 | warning | `badge-outline` | question-mark-circle |
| 판단 예외 (`exception`) | 예외 | error | `badge-outline` | flag |
| 결론 없음 (최신 결론 없음) | 미판단 | neutral | `badge-dash` | pencil-square |
| 검토 전 (`status` open) | `-` (`sr-only` "검토 전") | muted | 텍스트 | - |
| 검토 대기 (`status` concluded) | 검토 대기 | neutral | solid (`badge-neutral`) | clock |
| 승인 (`status` approved) | 승인 | success | solid | check-badge |
| 반려 (`status` rejected) | 반려 | error | solid | arrow-uturn-left |
| AI 생성 콘텐츠 | AI 제안 | accent | `badge-soft` + 점선 박스 | sparkles |
| 점수 구간 (`findings.score`) | 경미 0-24, 중 25-49, 상 50-74, 최상 75-100 | base-content | 숫자 + 5칸 막대 + 구간 텍스트 (색 없음) | - |
| 테스트 실행 (`test_runs.status`) | 실행 중, 완료, 일부 실패 | primary, success, warning | `progress-*` + 텍스트 | arrow-path (실행 중) |
| 룰 실행 (`test_run_rules.status`) | 대기, 실행 중, 완료, 미실행, 실패 | neutral, primary, success, neutral, error | 텍스트 + 아이콘 | clock, arrow-path, check, minus-circle, x-circle |
| GL 적재 (`ledger_imports.status`) | 대기, 적재 중, 완료, 실패 | neutral, primary, success, error | 텍스트 + 아이콘 | clock, arrow-path, check, x-circle |

- 위험도 낮음을 녹색으로 하지 않는 이유: "낮은 위험으로 플래그됨"은 "이상 없음"이 아니다. 녹색은 사람이 내린 결론(이상 없음, 승인)과 시스템 작업 완료에만 쓴다.
- 점수에 색을 쓰지 않는 이유: 점수는 룰 가중치 합(시스템 계산)이고, 위험도(AI 제안)와 같은 빨강/노랑을 쓰면 두 값이 같은 것으로 읽힌다. 점수는 크기(막대)와 구간 텍스트로만 보인다.
- "작성자 판단"과 "검토" 열은 따로 둔다. 판단은 최신 결론의 `outcome`, 검토는 `findings.status`에서 온다. 반려된 항목은 판단 배지(예: 예외)와 검토 배지(반려)가 함께 보인다.

### 3.3 대비 검증 (WCAG 2.x, sRGB 상대휘도로 직접 계산)

기준: 텍스트 4.5:1 이상, 비텍스트(경계, 포커스) 3:1 이상. "soft"는 daisyUI `badge-soft`의 배경(역할색 8%를 base-100과 oklab 혼합, 직접 계산한 근사값) 위 텍스트다. AI 박스는 5%를 쓰므로 계산한 8%보다 대비가 높다.

| 쌍 | Light | Dark | 기준 |
|---|---|---|---|
| 본문 on base-100 / base-200 | 16.40 / 15.02 | 13.91 / 15.30 | 4.5 |
| muted on base-100 / base-200 / base-300 | 6.38 / 5.84 / 4.90 | 6.86 / 7.55 / 5.02 | 4.5 |
| primary 텍스트 on base-100 / base-200 | 6.84 / 6.26 | 6.97 / 7.67 | 4.5 |
| primary-content on primary | 6.84 | 7.56 | 4.5 |
| error on base-100 / soft | 6.57 / 5.82 | 7.09 / 6.34 | 4.5 |
| warning on base-100 / soft | 6.51 / 5.76 | 8.96 / 7.84 | 4.5 |
| success on base-100 / soft | 6.39 / 5.68 | 7.77 / 6.91 | 4.5 |
| neutral on base-100 / soft | 7.69 / 6.74 | 8.07 / 7.16 | 4.5 |
| accent on base-100 / soft | 6.78 / 6.02 | 7.33 / 6.52 | 4.5 |
| *-content on solid: error, warning, success, neutral, accent | 6.57, 6.51, 6.39, 7.69, 6.78 | 7.68, 8.91, 7.81, 8.88, 7.76 | 4.5 |
| 본문 / muted on AI 박스 틴트 | 14.55 / 5.66 | 12.37 / 6.10 | 4.5 |
| line-strong vs base-100 / base-200 | 3.64 / 3.34 | 3.95 / 4.34 | 3.0 |
| 포커스 링(primary) vs base-100 / base-200 | 6.84 / 6.26 | 6.97 / 7.67 | 3.0 |

- `border-base-300` 구분선은 base-100 대비 1.30(light), 1.37(dark)이다. 의도적으로 3:1 미만이며 정보를 전달하지 않는다(행 구분 보조용). 정보는 텍스트와 아이콘으로 전달한다.
- 입력 경계 기본값(base-content 20%)은 약 1.51(light), 1.78(dark)이라 `line-strong`으로 교체한다.
- 차트나 열 지도는 MVP에 없다. 필요해지면 이 표에 추가한다.

### 3.4 타이포그래피

폰트: 시스템 폰트(2.3의 `--font-sans`, `--font-mono`). Pretendard 같은 웹폰트를 쓰려면 woff2를 `priv/static`에 두고 app.css `@font-face`로 불러오는 방식이 가능하나 MVP에서는 쓰지 않는다.

| 역할 | 클래스 | 크기 / 행간 | 굵기 | 용도 |
|---|---|---|---|---|
| 페이지 제목 | `text-xl` | 20 / 28 | semibold | 화면 제목 |
| 섹션 제목 | `text-base` | 16 / 24 | semibold | 카드, 섹션 헤더 |
| 본문, 폼, 테이블 셀 | `text-sm` | 14 / 20 | normal | 기본값 |
| AI 근거 등 긴 문단 | `text-sm leading-6` | 14 / 24 | normal | 한글 가독성 |
| 테이블 헤더 | `text-xs` | 12 / 16 | semibold, `text-muted` | 열 이름 |
| 메타, 캡션, 배지 | `text-xs` | 12 / 16 | normal, 배지는 medium | 보조 정보 |
| 요약 수치 (KPI) | `text-2xl tabular-nums` | 24 / 32 | semibold | stat_row |

- 12px는 보조 정보에만 쓴다. 판단에 필요한 정보는 14px 이상.
- 금액: sans + `tabular-nums` + 우측 정렬(`text-right`, 열 머리도 우측). 자릿수가 세로로 정렬된다.
- ID, 코드(entry_number, account_code, rule_code, 해시, 모델 ID): `font-mono slashed-zero whitespace-nowrap`. 0과 O, 1과 l 혼동을 막고 자르지 않는다.
- 날짜, 시각, 건수: `tabular-nums`.

## 5. 화면 구성

모두 데스크톱 우선(1024px 이상 보장). 1024px 미만에서는 S5의 왼쪽 큐가 본문 위로 접히고, 표는 컨테이너 안에서 가로 스크롤한다(페이지 전체는 가로 스크롤하지 않는다). 768px 미만의 편집은 MVP 범위 밖이다. 화면 6종의 시안은 [HTML 시안](2026-10-17-7-디자인-시스템-시안.html)에 라이트/다크로 있고, 값은 도메인 문서 7장의 합성 데이터(누리정밀 주식회사, FY2025)를 따른다.

### 5.1 라우트와 공통 셸

라우트는 메인 세션이 소유한다(설계 문서 12장). 모두 로그인 필요 `live_session` 안에 있고, engagement 하위 화면은 `on_mount`에서 멤버십을 확인한다. LiveView 이름은 설계 문서 1장을 따른다.

| 화면 | 경로 | LiveView | 내용 |
|---|---|---|---|
| S1 | `/engagements`, `/engagements/new` | `EngagementLive.Index` (`:index`, `:new`) | 내가 속한 감사 대상 목록, 생성 패널 |
| S2 | `/engagements/:id` | `EngagementLive.Show` | 개요, 멤버, GL 적재 목록, 테스트 실행 목록 |

| S4 | `/engagements/:id/runs/:run_id` | `TestRunLive.Show` | 룰 진행률, AI 트리아지 일괄 요청, 플래그 전표 목록 |

### 5.2 S1 감사 대상 목록

- 열: 회사명(링크), 회계연도, 결산일, 수행중요성(원), 최근 테스트(테스트 실행 배지), 검토 큐(건), 내 역할.
- "새 감사 대상"은 `:new` live_action으로 목록 위에 인라인 패널을 연다(모달 없음). 입력은 회사명, 회계연도, 결산일, 수행중요성 금액. 만든 사람은 그 감사 대상의 작성자 멤버가 된다는 안내를 패널 안에 둔다.
- 빈 상태: "감사 대상이 없습니다." + 생성 버튼.

### 5.3 S2 감사 대상 상세

- 헤더: 회사명 + `FY2025`, 결산일, 수행중요성, presence. 오른쪽에 주 행동 "GL 불러오기"(S3).
- `stat_row`: 최근 완료 실행 기준 전표, 라인, 검토 큐, 경미 적중. 실행이 없으면 `-`와 "테스트를 실행하면 채워집니다".
- 멤버: 이름, 이메일, 역할 배지(작성자/검토자). 추가 폼(이메일 + 역할)은 감사 대상의 작성자에게만 보인다. 한 사용자는 한 역할만 가진다.
- GL 적재 목록: 출처(업로드 파일명 또는 "합성 GL, 시드 N"), 상태(GL 적재 배지), 전표, 라인, 차변 합계(원), 대변 합계(원), 오류, 경고, 해시 앞 8자, 적재 시각. 완료된 행에는 "테스트 실행" 버튼(작성자만, 같은 적재에 실행 중인 테스트가 없을 때). `{:error, :run_in_progress}`는 버튼 옆 안내 문구로 보인다.
- 테스트 실행 목록: 시작 시각, 상태, 룰 완료 수, 적중 전표, 검토 큐, S4 링크.
- 실시간: `engagement:#{id}`의 `import_updated`, `test_run_updated`.

### 5.4 S3 GL 적재

- 두 방식을 탭으로 나눈다. CSV 업로드: `allow_upload` 1개, `.csv`, 20MB, 100,000행. 합성 GL 생성: 시드(정수, 비우면 생성기의 기본 시드), 목표 라인 수(기본 20,000). 같은 시드면 같은 GL이 나온다는 안내를 둔다(도메인 문서 7장).
- 제출하면 같은 화면에서 상태가 대기, 적재 중, 완료/실패로 바뀐다(`import_updated`). 완료 요약은 전표, 라인, 차변 합계 = 대변 합계, 경고 수와 "테스트 실행" 버튼.
- 실패하면 오류 표(행, 컬럼, 코드, 내용)를 보인다. 최대 100건, 넘으면 "그 밖에 N건". 내용은 코드별 고정 한글 문구이고 파일의 원래 값은 화면에 다시 쓰지 않는다. 경고(`period_mismatch`)는 접힌 별도 표.

| 코드 | 내용 |
|---|---|
| `missing_column` | 필수 컬럼이 없습니다 |
| `required` | 필수 값이 비어 있습니다 |
| `invalid_date` | 날짜 또는 일시 형식이 잘못되었습니다 |
| `invalid_number` | 금액은 원 단위 정수여야 합니다 |
| `both_sides` | 한 행에는 차변과 대변 중 하나만 있어야 합니다 |
| `unbalanced_entry` | 전표의 차변 합계와 대변 합계가 다릅니다 |
| `inconsistent_header` | 같은 전표의 헤더 값이 행마다 다릅니다 |
| `non_contiguous_entry` | 같은 전표의 행이 이어져 있지 않습니다 |
| `too_many_rows` | 행 수가 상한(100,000)을 넘었습니다 |
| `parse_error` | CSV 형식을 읽을 수 없습니다 |
| `period_mismatch` (경고) | 전기일의 월과 회계기간이 다릅니다 |

### 5.5 S4 테스트 실행

- 상단 `test_progress`: 룰 8개, 동시에 최대 4개 실행. 완료 뒤에는 룰별 적중 수가 남는다.
- 트리아지 바(작성자만, 실행 완료 뒤 활성): "검토 큐 52건 중 AI 미요청 52건" + "AI 트리아지 요청". 1회 최대 100건이라는 안내와, 요청하면 감사 로그에 요청자가 남는다는 안내. 요청 직후 대상 행의 AI 위험도는 "분석 중"이 되고 결과가 오는 대로 바뀐다.
- `filter_tabs`: 검토 큐(점수 25 이상) / 경미 적중(점수 25 미만). 보조 필터는 검토 상태(전체, 미판단, 검토 대기, 승인, 반려). AI 위험도 열과 필터는 검토 큐 탭에만 있다(경미 적중은 트리아지 대상이 아니다).
- 표 열: 전표번호, 전기일, 금액(원, 차변 합계), 점수(`score_meter`), 적중 룰(짧은 이름), AI 위험도, 작성자 판단, 검토. 기본 정렬은 점수 내림차순, 같으면 전표번호.
- 행의 전표번호가 S5 링크다.
- 실시간: `test_run:#{run_id}`의 `rule_progress`, `run_completed`와 `engagement:#{id}`의 `finding_updated`.

### 5.6 S5 전표 검토

위에서 아래 순서가 판단 순서다: 사실(전표) -> 룰 적중 -> AI 제안(점선) -> 사람 판단(실선) -> 서명.

1. 왼쪽 큐: S4의 현재 탭과 필터를 이어받은 목록, 현재 항목 표시, "다음 미판단".
2. 헤더: 전표번호(`h1`), `score_meter`, `risk_badge`, `conclusion_badge`, `review_badge`, presence.
3. 전표 사실: 전기일, 증빙일, 입력 일시(KST), 회계기간, 입력자, 승인자, 구분(수기/자동), 거래처, 적요. 룰 근거가 된 값(예: 입력자 = 승인자)은 같은 줄에 `text-warning` 아이콘과 `sr-only` 설명.
4. 전표 행: 행, 계정(코드 + 이름), 차변(원), 대변(원), 합계 줄과 "차대 일치".
5. `rule_hit_list`: 룰별 가중치와 근거, 맨 아래 "점수 55 = 20 + 10 + 25".
6. `ai_suggestion_card`.
7. `conclusion_form`.
8. 이력: 결론과 검토 결정을 시간순으로(작성자 결론 제출, 검토자 반려와 사유, 재제출, 승인). 결론은 append-only라 이전 결론도 남는다.
9. `sign_off_bar` (화면 아래 고정).

- 실시간: 같은 finding의 `finding_updated`를 받으면 다시 읽는다. presence의 `view`는 `"finding:#{id}"`라서 같은 전표를 보는 사람만 헤더에 보인다.
- AI 제안과 사람 판단은 시각적으로 분리되고, AI는 결론 라디오를 미리 고르지 않는다.

### 5.7 S6 감사 로그

- 헤더 고정 문구: "읽기 전용. 기록은 수정하거나 삭제할 수 없습니다."
- 필터: 행위자 유형(전체, 사람, AI, 시스템), 대상(전표번호나 실행 등 subject). 서버 필터이며 `AuditTrail.list_events/3`의 `actor_type`, `subject` 옵션을 쓴다.
- 최신이 위. `stream`으로 그리고 아래 "더 보기"는 `before_seq`로 이어 읽는다.
- 새 이벤트(`audit_appended`)는 목록에 바로 끼우지 않고 상단에 "새 이벤트 N건" 버튼을 띄운다. 읽던 위치가 밀리지 않게 하기 위해서다.
- 한 행 = `audit_event_item` 하나: seq, 일시(KST, 초까지), 행위자, 행위, 대상, 요약, payload 펼침.

## 6. 금액, 날짜, ID 표기 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| KRW 금액 (표) | 원 단위 정수, 천 단위 쉼표, 통화 기호 없음, 열 머리에 "(원)". DB의 `numeric(18,2)`는 소수부가 0이면 생략. 0이 아닌 소수부는 숨기지 않고 2자리로 표시한다(데이터 오류 노출). | `12,000,000` |
| KRW 금액 (문장) | 숫자 뒤에 "원" | `수행중요성 225,000,000원` |
| KRW 금액 (KPI 요약) | 억/만 단위 축약 허용, 전체 값은 `title`. 표에서는 축약 금지. | `2억 2,500만원` |
| 음수 | 앞에 hyphen-minus. 괄호와 빨간색은 쓰지 않는다(색 비의존). | `-1,250,000` |
| 0 | 차변/대변 열은 `-`(스크린리더용 `sr-only` "0"), 합계와 요약은 `0` | `-` |
| 값 없음 | `-` + `sr-only` "없음" | `-` |
| 비율, 진행률 | 비율 소수 1자리, 진행률 정수 | `62.5%`, `62%` |
| 건수 | 천 단위 쉼표 + 단위 | `8,341건` |
| 날짜 | `YYYY-MM-DD`. "2025년 12월 31일" 형식과 요일은 쓰지 않는다. | `2025-12-31` |
| 일시 | 표시는 KST 24시간 `YYYY-MM-DD HH:MM`. 감사 로그와 상세는 초까지. 열 머리에 "(KST)"를 한 번만 쓰고, 단독 표기는 뒤에 " KST". 시스템 시각은 `<time datetime>`과 `title`에 UTC 원문(GL의 `entered_at`은 아래 KST 항목). | `2025-12-30 23:42` |
| entry_number | 원문 그대로 mono, 선행 0 보존, 줄바꿈과 말줄임 금지. 행 참조는 뒤에 `L2`(muted). | `JE-000123 L2` |
| 계정 | 코드는 mono, 이름은 sans | `4110 제품매출` |
| 회계연도, 기간 | 연도 `FY2025`, 기간은 숫자, 13은 `13(결산조정)` | `FY2025`, `12` |
| 사용자 | 표시 이름 우선, ID는 `title`과 상세에서 mono | `김작성` |
| 해시, 모델 ID | 해시는 앞 8자 mono + 전체는 `title`, 모델 ID는 전체 mono | `a1b2c3d4` |
| 긴 텍스트 (적요) | 목록에서는 1줄 `truncate` + `title`, 상세에서 전체 | |

- KST: 시스템 시각(`inserted_at` 등)은 UTC로 저장하고 표시할 때만 고정 오프셋 +9시간을 더한다. KST는 DST가 없어 tzdata 의존성이 필요 없다(메인 세션 결정). GL의 `entered_at`은 시간대 없는 KST 값이라 변환 없이 그대로 보이고, `<time datetime>`에도 오프셋을 붙이지 않는다.
- 포맷 함수는 한 모듈(`TickmarkWeb.Format`)에 모아 컴포넌트와 LiveView가 같이 쓴다.

## 7. 접근성

### 7.1 검토 화면의 키보드 흐름

| 순서 | 영역 | 키보드 동작 |
|---|---|---|
| 1 | "본문으로 건너뛰기" 링크 | 첫 Tab에서 나타나고 Enter로 본문 이동 (`sr-only focus:not-sr-only`) |
| 2 | 상단 바 | Tab. 현재 위치는 `aria-current="page"` |
| 3 | 큐 목록 | 항목은 링크, Tab 이동. 현재 항목 `aria-current="true"`. "다음 미판단" 버튼 |
| 4 | 전표 제목 (`h1`, `tabindex="-1"`) | 항목 전환(`live_patch`) 뒤 프로그램으로 포커스를 옮기고 `aria-live`로 "JE-000123 검토 화면" 안내 |
| 5 | 전표 행 테이블 | 스크롤 영역 `tabindex="0" role="region" aria-label="전표 행"`. 방향키 스크롤 |
| 6 | 룰 적중 | `<details>` 요약에서 Enter/Space로 펼침 |
| 7 | AI 제안 | `role="region" aria-label="AI 제안, 사람의 판단 아님"`. 내부 `<details>`만 포커스 대상 |
| 8 | 작성자 판단 | Tab으로 라디오 그룹에 진입, 방향키로 선택, Tab으로 코멘트, Ctrl+Enter 또는 저장 버튼 |
| 9 | sign-off bar | 반려, 승인 버튼. 비활성 이유는 `aria-describedby`. 반려 패널은 Esc로 닫고 포커스가 반려 버튼으로 돌아온다 |

- 단일 문자 단축키는 쓰지 않는다(WCAG 2.1.4). 수정자 키 조합은 Ctrl+Enter만 쓴다.
- 판단 저장 뒤 포커스는 저장 버튼에 남기고 결과는 `aria-live="polite"` flash로 알린다.

### 7.2 포커스와 가림

- 모든 포커스 가능 요소에 2px primary 링, offset 2px (3.3 대비 표 기준 6.26 이상). `outline: none`을 쓰지 않는다.
- sticky 헤더(약 36px)와 sign-off bar(약 56px)가 포커스를 가리지 않도록 스크롤 컨테이너에 `scroll-padding-top: 2.5rem`, `scroll-padding-bottom: 4rem`.
- 클릭 대상은 24px 이상(WCAG 2.2 2.5.8). 기본 컨트롤 32px, `btn-sm` 25.6px.

### 7.3 색이 유일한 신호가 아니다

| 신호 | 색 | 함께 쓰는 수단 |
|---|---|---|
| 위험도 | error / warning / neutral | 텍스트 높음, 중간, 낮음 + 아이콘 모양 3종 |
| 작성자 판단 | success / warning / error | 텍스트 + 아이콘 + outline 모양 |
| 검토 상태 | neutral / success / error | 텍스트 + 아이콘 + solid 모양 |
| AI 콘텐츠 | accent | "AI 제안" 라벨, sparkles 아이콘, 점선 경계 |
| 룰 대상 전표 행 | warning | 좌측 굵은 막대 + 아이콘 + `sr-only` "룰 대상" |
| 진행률 | primary | 퍼센트 숫자와 "5 / 8" 텍스트 |
| 점수 | 없음 | 숫자 + 5칸 막대 + 구간 텍스트(경미, 중, 상, 최상) |
| 음수 금액 | 없음 | hyphen-minus 부호 |
| presence | neutral | 이니셜 + 이름 툴팁 + `sr-only` 목록 |

### 7.4 그 밖의 규칙

- `<html lang="ko">`. 표는 `caption`(sr-only), `th scope="col"`, 숫자 열 우측 정렬.
- 실시간 갱신: 진행률 텍스트는 10% 단위로 바뀔 때만 `aria-live` 갱신. 감사 로그 신규 이벤트는 "새 이벤트 N건" 요약만 알린다.
- 모션은 `motion-safe:`로만 적용(스피너, 하이라이트). 모달은 쓰지 않아 포커스 트랩 문제가 없다.
- 검증 방법: (1) 라이트/다크 각각 키보드만으로 S5 화면(5.6)을 끝까지 수행, (2) 브라우저 도구(Lighthouse 등)로 접근성 점검 - 새 의존성 없이 수동 수행, (3) 3.3 표의 hex 값이 바뀌면 대비를 다시 계산해 갱신.
