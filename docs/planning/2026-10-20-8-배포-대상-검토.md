## 1. 조건

- 사용자 조건 (10/20): 가급적 무료. Vercel 선호.
- 앱 조건: Phoenix LiveView 는 브라우저와 WebSocket 을 계속 열어 둔다. Oban 은 같은 BEAM 안에서 1초마다 큐를 확인하는 상주 프로세스다. PubSub 와 Presence 는 같은 노드 (또는 연결된 노드) 에 있어야 한다. 그래서 요청마다 떴다 사라지는 서버리스 함수와 맞지 않는다.
- 사용 기간: 지원 마감 (10/25) 뒤 면접까지 1-3개월. 데이터는 합성 데이터라 잃어도 시드로 다시 만들 수 있지만, 면접 직전에 DB 가 지워지면 곤란하다.

## 3. 제안

**앱은 Render Free 웹 서비스, DB 는 Neon Free.** Vercel 은 쓰고 싶으면 앱으로 링크하는 정적 소개 페이지에만 쓴다.

- 이유: 둘 다 무료이고, WebSocket 길이 제한이 없고, Neon 데이터는 만료되지 않는다. Render 가 잠들면 Oban 폴링도 멈춰 Neon 도 잠들어 CU-hours 를 아낀다.
- Render 무료 Postgres 는 쓰지 않는다. 30일 뒤 만료되어 면접 기간에 사라질 수 있다.
- 깨어 있게 하는 외부 ping 은 두지 않는다. Oban 이 Neon 을 계속 깨워 월 중순에 CU-hours 가 바닥날 수 있다 (조사 에이전트 추정: 상시 가동 시 월 약 182 CU-hours). 대신 면접 2-3분 전에 URL 을 한 번 연다.
- 첫 접속 약 1분 지연이 싫고 월 몇 달러를 낼 수 있으면 Fly.io 머신 + Neon 으로 바꾼다. 앱 구성 (release, Dockerfile, runtime.exs) 은 같다.
- Vercel 을 앱 호스트로 쓰지 않는 이유: Container Runtime 과 WebSocket 이 베타이고, Hobby 의 연결 최대 300초 때문에 LiveView 가 5분마다 끊기고, 인스턴스가 나뉘면 PubSub 와 Presence 가 갈라지며, 축소되면 Oban 이 멈춘다.

## 4. 결정되면 할 일 (5.4)

- `mix phx.gen.release` 로 release 와 (필요하면) Dockerfile 을 만든다. `config/runtime.exs` 의 `DATABASE_URL`, `SECRET_KEY_BASE`, `PHX_HOST` 는 플랫폼 환경 변수로만 넣는다. 저장소에 값을 두지 않는다.
- Neon 은 TLS 가 필수라 `ssl: true` 를 켠다. Oban 의 Postgres notifier 는 LISTEN/NOTIFY 를 쓰므로 Neon 의 pooled 연결이 아닌 직접 연결 문자열을 쓴다 (또는 `Oban.Notifiers.PG` 로 바꾼다).
- `ANTHROPIC_API_KEY` 는 넣지 않아도 Fake 로 동작한다. 넣으면 사용 한도를 확인한다.
- 배포 뒤 시드로 데모 데이터를 넣고 S1-S6 을 외부 접속으로 확인한다.
- 사용자가 할 일: Render 와 Neon 계정 만들기, Render 에 GitHub 저장소 연결, 환경 변수 입력 (메인이 목록을 준다).
