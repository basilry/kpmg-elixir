## 1. 목표

2026-10-23까지 3분 안에 시연할 수 있는 MVP를 만들고, GitHub 링크를 첨부해 지원서를 낸다(마감 10-25, 조기 마감 가능). 지원 후에도 면접 전까지 2단계를 계속 진행한다.

## 2. 핵심 시나리오 (MVP)

1. 작성자(preparer)가 감사 대상(engagement)을 만든다. 입력값은 회사명, 회계연도, 결산일, 수행중요성 금액이다.
2. 합성 총계정원장(GL) CSV를 업로드하거나, 내장 생성기로 만든다.
3. 테스트를 실행하면 룰 기반 분개 테스트가 병렬로 돌고, 진행률이 화면에 실시간으로 보인다.
4. 걸러진 전표마다 AI 에이전트가 위험도, 근거, 추가 감사절차를 제안한다. 제안만 하고 결론은 내리지 않는다.
5. 작성자가 각 항목에 판단(이상 없음 / 추가 확인 필요 / 예외)과 코멘트를 남긴다.
6. 검토자(reviewer)가 검토 후 승인하거나 반려한다. 작성자 본인은 승인할 수 없다(직무분리).
7. 위의 모든 행위(사람, AI, 시스템)를 감사 로그에서 시간순으로 볼 수 있다.

## 4. 범위 밖

- 실제 고객 데이터, 외부 ERP 연동

## 5. 분개 데이터 계약 (GL CSV 컬럼)

도메인 문서(룰 정의)와 설계 문서(스키마)가 동시에 참조하는 공통 계약이다. 컬럼을 추가하거나 바꾸려면 메인 세션의 승인을 받는다.

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `entry_number` | string | O | 전표번호. 같은 번호의 행들이 하나의 전표를 이룬다 |
| `line_number` | integer | O | 전표 내 행 번호 (1부터) |
| `posting_date` | date | O | 전기일 (장부에 반영된 날) |
| `document_date` | date | O | 증빙일 (거래가 실제 일어난 날) |
| `entered_at` | datetime | O | 시스템 입력 일시 (KST, 시간대 판단용) |
| `fiscal_year` | integer | O | 회계연도 |
| `fiscal_period` | integer | O | 회계기간 (1~12, 결산 조정은 13) |
| `account_code` | string | O | 계정 코드 |
| `account_name` | string | O | 계정명 |
| `debit` | decimal | O | 차변 금액 (없으면 0) |
| `credit` | decimal | O | 대변 금액 (없으면 0) |
| `description` | string | | 적요 |
| `counterparty` | string | | 거래처 |
| `entered_by` | string | O | 입력자 사용자 ID |
| `approved_by` | string | | 승인자 사용자 ID (자동 전표는 비어 있을 수 있음) |
| `source` | string | O | `manual`(수기) 또는 `system`(자동) |

검증 규칙:

- 한 행은 차변과 대변 중 정확히 하나만 0보다 크다.
- 같은 `entry_number`의 차변 합계와 대변 합계가 같아야 한다.
- 금액은 KRW 원 단위 정수이고, 저장은 `numeric(18,2)`로 한다.
