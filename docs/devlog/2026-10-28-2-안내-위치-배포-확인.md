## 결정과 트레이드오프

1. **브라우저 패널 대신 새 프로필 headless Chrome**: 브라우저 패널은 10-27 점검의 로그아웃으로 세션에 `:demo_auto_login_off` 가 남아 `/` 가 홈에 머문다. 쿠키를 지우면 같은 패널의 다른 사이트 세션까지 건드린다. 새 프로필은 처음 온 방문자와 같아서 실제 자동 로그인 안내가 뜬다. 대신 운영 DB 에 세션 토큰 행이 하나 생겨서 `/` 는 한 번만 열었다.
2. **375px 는 다시 열지 않고 줄여서 잼**: 폭에 따른 배치는 CSS 가 정하고 서버 응답은 폭과 관계없다. 다시 열면 토큰 행이 하나 더 생긴다. 대신 375px 로 처음 그린 화면은 보지 않았다.
3. **가려짐 판정은 `elementFromPoint`**: 좌표만 비교하면 드롭다운과 안내가 겹치는 자리에서 어느 쪽이 위인지 모른다. 요소 가운데 점에서 맨 위에 있는 요소가 그 요소인지 봤다. 메뉴는 `<details>` 라 `open` 속성을 넣어 열었다. 실제 클릭은 하지 않았으므로 "눌린다" 는 가운데 점 판정으로 갈음한 것이다. 판정 방법은 로컬 확인 (10-28-1) 과 같다.
4. **로그아웃은 하지 않음**: `log_out_user` 는 세션 토큰 행을 지우므로 로그아웃하면 행이 남지 않는다. 로그아웃 흐름은 10-27 에 www 에서 확인했고, 이번 확인은 위치만 보면 돼서 생략했다. 그래서 행 1개가 남는다 (가이드 6장의 토큰 행).
5. **긴 문구에서 본 안내 크기**: 로컬 확인은 짧은 "로그인했습니다." 안내로 해서 상자가 64-111 이었다. 자동 로그인 안내는 세 줄이라 64-170 이다. 619px 에서 표 머리 오른쪽을, 375px 에서 제목 줄과 표 머리, 첫 행 윗부분을 덮는다. 누르면 닫히고 메뉴는 늘 위에 있어 두었다 ([안내 위치 devlog](2026-10-28-1-안내-위치와-사용자-메뉴.md) 트레이드오프 5).
6. **새 빌드 감지는 10-27 과 같은 방법**: 대시보드 대신 새 문서 주소의 200 을 썼다. `/docs` 위키는 빌드 때 문서를 컴파일하므로 200 이면 새 빌드다. `/` 로 보면 요청마다 토큰 행이 생긴다.

## 막힌 점과 해결

- 브라우저 패널로는 자동 로그인을 다시 볼 수 없었다 (위 1번). 새 프로필의 headless Chrome 을 띄우고 Node 의 내장 `WebSocket` 으로 DevTools 프로토콜에 붙는 짧은 스크립트를 썼다. 스크립트는 저장소 밖 임시 폴더에 두었다.

## Elixir 학습 포인트

- **flash 가 리다이렉트를 건너는 방식**: `Phoenix.Controller.fetch_flash/2` 는 세션의 `"phoenix_flash"` 를 읽어 `conn.assigns.flash` 에 두고 `register_before_send` 로 콜백을 건다. 응답 직전에 flash 가 비어 있지 않고 상태가 300..308 이면 세션에 다시 넣고, 그 밖의 응답이면 세션에서 지운다. 자동 로그인 안내가 `/` -> `/` -> `/engagements` 리다이렉트 두 번을 지나 `/engagements` 에서 보이는 이유다. `/engagements` 의 200 응답에서는 세션의 flash 가 지워진다.
- **운영 빌드의 CSS 클래스**: `top-16` 은 `core_components.ex` 한 곳에서만 쓴다. Tailwind 는 소스에 나온 클래스만 CSS 로 만들고, Dockerfile 의 `mix assets.deploy` 가 빌드 때 이것을 돌린다. 운영에서 계산된 `top` 이 64px 이므로 운영 CSS 에 `top-16` 규칙이 들어 있고, `.toast-top` 의 `top` 보다 이긴다 (층 규칙은 [안내 위치 devlog](2026-10-28-1-안내-위치와-사용자-메뉴.md) 학습 포인트).
