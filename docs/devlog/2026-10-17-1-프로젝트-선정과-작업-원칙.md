## 작업 원칙 (AGENTS.md)

사용자가 정한 5가지 원칙을 [AGENTS.md](../../AGENTS.md)로 옮겼다.

1. 개발 과정을 docs/devlog에 계속 기록한다.
2. 문서 파일명은 `{YYYY-MM-DD}-{시퀀스}-{제목}.md`로 한다.
3. 설계, 기획, 디자인 문서는 docs 아래 카테고리 폴더로 관리한다 (devlog, planning, architecture, design, domain).
4. 커밋 메시지는 한글로 쓴다 (type과 scope만 영어).
5. 팀 에이전트로 병렬 개발하고, 메인 세션이 오케스트레이션한다.

원칙을 구체화하면서 내린 결정:

| 결정 | 이유 | 대안 |
|---|---|---|
| 시퀀스는 카테고리별이 아니라 docs 전체 기준으로 센다 | 날짜+시퀀스만으로 시간순이 유일하게 정해진다 | 폴더별 시퀀스 (번호가 겹쳐 혼란) |
| 살아있는 문서는 파일명을 유지하고 Changelog로 갱신한다 | 링크가 깨지지 않는다 | 갱신마다 새 파일 (중복 문서가 쌓임) |
| 병렬 워커의 문서 파일명은 메인 세션이 미리 배정한다 | 동시에 같은 시퀀스를 쓰는 충돌을 막는다 | 워커가 직접 계산 (경합) |
| mix.exs, config, router, migrations는 메인 세션만 고친다 | 마이그레이션 순서, lock, 라우터는 병렬로 고치면 거의 항상 충돌한다 | 워커 자유 수정 후 병합 (충돌 해결 비용이 큼) |
| 코드 워커는 git worktree에서 격리한다 | 같은 체크아웃에서 동시 수정을 막는다 | 같은 체크아웃 + 파일 소유권만 (실수 시 덮어씀) |
| Elixir 코드 파일명은 snake_case | Elixir 관례이며 모듈명과 경로가 대응한다. 전역 규칙(하이픈)과 충돌하므로 AGENTS.md에 예외로 적었다 | 하이픈 (Elixir 생태계와 어긋남) |
| Phoenix가 생성한 AGENTS.md는 `refs/phoenix-guidelines.md`로 분리했다 | 원문이 약 22KB라 CLAUDE.md에서 매 턴 불러오면 비용이 크다. 코드 작업 전에만 읽도록 필독 규칙을 걸었다 | 하나로 합치기 (매 턴 수천 토큰 추가) |

## 한 일

- 툴체인 설치: Homebrew로 Elixir 1.20.4 / Erlang/OTP 29를 설치했다. Phoenix 설치기는 1.8.15이고, PostgreSQL은 기존 Postgres.app 16.4를 쓴다.
- `mix phx.new tickmark --binary-id --no-install`을 임시 폴더에서 생성한 뒤 저장소로 복사했다. 기존 AGENTS.md와 충돌하지 않게 하려고 임시 폴더를 거쳤다.
- 첫 병렬 라운드를 시작했다. 도메인 문서(분개 테스트 룰)와 설계 문서(구조와 데이터 모델)를 워커 2명이 동시에 쓰고, 그동안 메인 세션은 스캐폴딩을 맡았다. 두 문서가 공유하는 계약은 MVP 문서 5장의 GL 컬럼 정의다.

## Elixir 학습 포인트

- `mix`는 빌드, 의존성, 태스크 실행을 한 도구로 처리한다 (npm + make에 가깝다). `mix phx.new`도 Hex에서 받은 archive가 제공하는 태스크다.
- `--binary-id`를 주면 생성기가 UUID 기본 키를 쓴다. 2단계에서 Ash를 도입할 때 Ash의 기본값(`uuid_primary_key`)과도 맞는다.
- Phoenix 1.8은 `mix precommit` alias를 기본 제공한다. 내용은 `compile --warnings-as-errors`, `deps.unlock --unused`, `format`, `test`이고, 커밋 전 검증 명령으로 그대로 쓴다.
