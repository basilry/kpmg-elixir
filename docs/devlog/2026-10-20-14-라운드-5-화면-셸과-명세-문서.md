## 결정과 트레이드오프

- **화면 워커 둘을 파일 단위로 나눴다.** 대안은 "화면 묶음" 으로 나누는 것이었다. 예를 들어 홈과 로그인을 한 워커에게 주는 방식이다. 그러면 두 워커가 `layouts.ex` 와 `app.css` 를 함께 고치게 되어 거의 확실히 충돌한다. 대신 셸, 홈, 오류 화면은 F1, 인증 화면은 F2 에게 줬다. F2 는 인증 화면의 폭을 자기 마크업 안에서 좁히게 했다 (계약 12.4). 병합 충돌은 0건이었다.
- **S5 의 상단 바 연결은 F1 병합 뒤 메인이 했다.** S5 (`finding_live/*`) 는 그때 W6 소유였다. F1 이 같이 고치면 W6 와 충돌한다. 대가는 S5 연결이 커밋 하나 늦어지는 것뿐이었다 (f300f2f).
- **기본 로케일 `ko` 는 워커 시작 전에 메인이 넣었다.** ko 번역이 없는 msgid 는 영어 원문으로 돌아간다. 그래서 이 설정만으로는 화면과 테스트가 바뀌지 않아 미리 넣어도 안전했다. F2 는 PO 파일만 추가하면 됐다.
- **AI 요청 단추의 권한 확인은 Triage 에 맡겼다.** 대안은 LiveView 에서 역할, 점수, 상태를 먼저 확인하고 통과할 때만 Triage 를 부르는 것이었다. 화면은 단추를 숨기거나 비활성으로 만들 뿐이다. 실제 확인은 `request_finding_triage/2` 가 한다. 역할은 DB 의 멤버십으로 확인하고, 점수와 상태는 finding 행을 잠근 뒤 다시 본다. 검토자의 위조 클릭, 다른 탭에서 이미 요청한 낡은 단추, 두 탭의 동시 클릭이 모두 같은 경로로 막힌다. 확인 규칙이 두 곳에 있으면 한쪽만 바뀌는 일이 생긴다.
- **시드는 context 를 거친다.** 대안은 `Repo.insert_all` 로 행을 직접 넣는 것이었다. 더 빠르지만 감사 이벤트, 상태 전이, 방송을 따로 흉내 내야 한다. context 를 거치면 시드가 "S1 생성 -> S3 적재 -> S2 실행" 시나리오를 처음부터 끝까지 한 번 돌리는 셈이다. 데모 데이터의 감사 로그도 실제와 같다. 대가는 Oban job 을 기다리는 3.4초다.
- **D1, D2 는 기준 커밋을 고정해 썼다.** 진행 중인 F1, F2, W6 코드를 쫓아가면 문서가 계속 어긋난다. f5f7f78 을 기준으로 쓰고, 진행 중인 부분은 "불일치" 표에 남기게 했다. 대가로 병합 시점에 이미 낡은 내용이 있었고, 메인이 14장에 차이를 적어 보완했다.
- **D1, D2 는 서로의 ID 를 참조하지 않았다.** 동시에 쓰는 문서라 상대의 FN, REQ 번호를 알 수 없다. D2 는 화면 (S1-S6) 과 계약 절을 참조했다. FN 과 IF 의 교차 링크는 아직 달지 않았다.

## 막힌 점과 해결

- **W6 의 부재 단언이 F2 병합 뒤 늘 참이 됐다.** W6 테스트는 S5 결론 폼에서 화면 전용 문구가 기본 오류 문구를 대신하는지 확인했다. 방법은 `"can't be blank"` 가 화면에 없다는 `refute` 였다. F2 의 ko 번역이 들어가자 기본 문구 자체가 "필수 입력 항목입니다." 로 바뀌었다. 그 뒤로는 영어 문자열이 화면에 없다는 단언이 코드가 어떻든 참이다. 테스트는 통과하지만 아무것도 확인하지 않는다. F2 병합 직후 이를 찾아 한글 기본 문구가 없는지 확인하도록 고쳤다 (9a20b16). 부재 단언은 그 문자열이 실제로 나올 수 있는 조건에서만 의미가 있다. 라운드 3 의 `#imports th` 단언과 같은 종류의 실수다.
- **`whitespace-pre-wrap` 아래 템플릿 공백 (8502ed7).** HEEx 는 `<%= if ... do %>` 블록 안의 줄바꿈과 들여쓰기를 텍스트로 출력한다. 보통은 브라우저가 공백을 합쳐 보이지 않는다. 그런데 여러 줄 적요를 보이려고 `whitespace-pre-wrap` 을 준 칸에서는 그대로 빈 줄이 된다. `optional_value` 를 if 블록 대신 함수 두 절 (값이 있을 때, 없을 때) 로 나눴다. 여러 줄이 필요 없는 칸에서는 pre-wrap 을 뺐다.
- **탭 제목 "Tickmark | Tickmark".** 루트 레이아웃의 `.live_title` 은 `page_title` 이 없으면 기본값 "Tickmark" 에 접미사 " | Tickmark" 를 붙인다. F1 은 홈에서 같은 문제를 찾아 고쳤다. 인증 화면 4개는 F2 범위였지만 F2 테스트가 탭 제목을 보지 않아 남아 있었다. 브라우저에서 찾았다.

## Elixir 학습 포인트

- **Gettext 의 도메인과 로케일.** `CoreComponents.translate_error/1` 은 changeset 오류의 msgid (예: `"can't be blank"`) 를 `errors` 도메인에서 찾는다. 기본 로케일이 `ko` 이고 `priv/gettext/ko/LC_MESSAGES/errors.po` 에 그 msgid 가 있으면 번역을, 없으면 원문을 돌려준다. 그래서 스키마 코드를 바꾸지 않고 PO 파일만으로 문구가 바뀐다. 한국어는 복수형을 구분하지 않으므로 PO 헤더가 `nplurals=1` 이고 `msgstr[0]` 하나만 쓴다.
- **`mix run` 시드와 Oban.** `mix run priv/repo/seeds.exs` 는 애플리케이션 전체를 시작한 뒤 스크립트를 돈다. Oban 도 떠서 백그라운드에서 job 을 처리한다. 스크립트가 끝나면 VM 이 바로 멈추므로, 기다리지 않으면 적재나 룰 실행이 중간에 끊긴다. 시드는 `Enum.reduce_while/3` 와 `Process.sleep/1` 로 상태를 폴링한다. 테스트에서는 `Oban.Testing` 이 job 을 같은 프로세스에서 바로 돌리므로 이런 대기가 필요 없다.
- **함수 컴포넌트 레이아웃.** Phoenix 1.8 은 라우터에서 앱 레이아웃을 씌우지 않는다. 각 LiveView 가 `<Layouts.app ...>` 로 자기 본문을 감싼다. 그래서 화면마다 `engagement`, `active` 같은 attr 을 넘겨 상단 바를 바꿀 수 있다. attr 기본값 (`nil`, `[]`) 이 "감사 대상 밖" 상단 바가 된다.
- **잠금 뒤 재확인 (`Ecto.Multi.run`).** `request_finding_triage/2` 는 역할을 확인한 뒤 Multi 의 첫 단계에서 finding 을 `FOR UPDATE` 로 잠근다. 그 안에서 점수와 상태 (`queued` 인지) 를 다시 본 뒤 상태 변경, job 생성, 감사 이벤트를 한 트랜잭션에 넣는다. 화면이 본 상태와 지금 상태가 달라도 결과가 맞다.
