## 결정과 트레이드오프

1. **목업인가**: 데이터와 AI, 메일은 가짜다 (합성 GL, Fake AI 클라이언트, Swoosh Logger). DB (Neon), Oban job, 감사 로그, 인증은 진짜이고 기록이 남는다. 그래서 자동 로그인은 "누구나 작성자로 진짜 기록을 남긴다" 는 뜻이다. 합성 데이터라서 받아들였다.
2. **`/` 에서만**: 대안 (a) 모든 보호 페이지에서 자동 로그인 (`require_authenticated_user` 를 바꿈). 링크 공유는 편하지만 인증 plug 전체가 데모 분기를 갖고, 로그아웃해도 아무 페이지나 열면 다시 로그인된다. 대안 (b) 별도 `/demo` 경로. 가장 분리되지만 요청한 "메인화면" 이 아니고 지원서 URL 이 바뀐다. 홈 컨트롤러 한 곳에 두면 고칠 곳이 적고 끄기도 쉽다.
3. **로그아웃하면 멈춤**: 표시가 없으면 로그아웃 뒤 `/` 에서 다시 작성자가 되어 검토자로 갈 길이 없다. 쿠키 대신 세션에 둔 이유는 다시 로그인할 때 `renew_session` 이 세션을 비우면서 저절로 지워지기 때문이다. 세션 쿠키라 브라우저를 닫으면 사라지는 점은 받아들였다.
4. **설정 위치**: `prod.exs` 에서 켜고 환경 변수로 덮는다. 대안은 `render.yaml` 에 변수를 넣는 것인데, 이 파일의 `plan: free` 가 대시보드 플랜 (0.5c-512mb) 과 달라 바꾼 push 가 동기화되면 Free 로 돌아갈 수 있어 피했다 (가이드 5.3절). dev 와 test 는 꺼짐이라 기존 테스트와 로컬 메일 로그인 흐름은 그대로다.
5. **작성자만**: 데모 순서가 작성자의 결론 제출에서 시작한다. 검토자로 자동 로그인하면 그 흐름부터 볼 수 없다.

위험은 가이드 6장에 행으로 남겼다.

- 방문자 모두가 작성자라서 남긴 기록이 영구히 남고 서로 보인다.
- 쿠키 없는 `GET /` 마다 세션 토큰 행이 생긴다. 만료 토큰을 지우는 job 은 없다. Render 상태 확인이 `/` 를 부르는지는 확인 필요.
- 자동 로그인 직후 10분 동안 sudo 모드라서 설정 화면에서 작성자 비밀번호를 바꿀 수 있다. 비밀번호를 쓰지 않는 자동 로그인에는 영향이 없다.
- `/` 가 아닌 주소로 바로 들어오면 로그인 화면이 뜬다.

## 막힌 점과 해결

- 변이를 되돌리려고 `git checkout -- lib/tickmark_web/user_auth.ex` 를 썼다가 커밋하지 않은 로그아웃 수정까지 지웠다. 미리 떠 둔 사본으로 되살리고 diff 로 확인했다. 그 뒤로는 변이 전에 사본을 떠 두고 사본으로 되돌린다.
- 브라우저에서 로그아웃 링크를 눌러도 처음에는 반응이 없었다. 링크가 닫힌 `<details id="topbar-user-menu">` 안에 있어서였다. 메뉴를 연 뒤 누르니 됐다. 이번 변경과는 관계없다.

## Elixir 학습 포인트

- `log_in_user/3` 는 `user_return_to || signed_in_path(conn)` 로 보낸다. 로그인 전 conn 의 `signed_in_path` 는 `/` 라서 흐름이 `/` -> 302 `/` -> 302 `/engagements` 다. 두 번째 `/` 는 이미 로그인한 경우의 분기가 받는다.
- `renew_session` 은 `configure_session(renew: true)` 와 `clear_session` 으로 세션 고정 공격을 막는다. 남길 값은 비운 뒤에 다시 넣어야 한다. 생성기 주석도 같은 방법을 안내한다.
- flash 는 `conn.private` 에 있다가 `before_send` 에서 세션에 쓰인다. 응답이 3xx 이면 남고 아니면 지워진다. 그래서 `clear_session` 뒤에도 사라지지 않고, 리다이렉트 두 번을 지나 `/engagements` 에 안내가 보인다.
- `Config.Reader.read!/2` 로 설정 파일을 테스트에서 직접 읽어 운영 기본값과 환경 변수 해석을 확인했다. `runtime.exs` 는 prod 로 읽으면 `DATABASE_URL` 이 없어 raise 하므로 dev 로 읽는다. 덮어쓰기 코드가 prod 블록 밖에 있어 결과는 같다.
- Application env 와 OS env 를 바꾸는 테스트는 `async: false` 로 둔다. ExUnit 은 async 모듈을 먼저 돌리고, sync 모듈은 그 뒤에 하나씩 돌린다.
