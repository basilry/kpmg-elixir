## 결정과 트레이드오프

- **비밀값은 내가 입력하지 않는다.** DB 주소, secret, 데모 비밀번호를 내가 화면에 치면 대화 기록에 남는다. 가이드 3장 규칙 ("값은 Render 대시보드에만") 을 지키려고 그 칸만 사용자가 채웠다. 대가는 왕복이 몇 번 늘어난 것이다.
- **데모 데이터는 읽기만 했다.** 실행 시작, 결론 제출, 승인, AI 요청을 누르면 `audit_events` 에 영구히 남는다 (append-only). 면접에서 보여 줄 첫 상태 (이벤트 #1-#6, 검토 큐 52, 결론 0) 를 지키려고 페이지를 여는 것까지만 했다. 그래서 쓰기 경로 (결론, 승인, AI 트리아지) 는 배포 환경에서 확인하지 않았다. 같은 코드가 로컬 테스트 588개와 10/20 브라우저 확인을 통과한 것으로 갈음한다.
- **값 확인을 배포 결과로 대신했다.** 가려진 값을 미리 볼 방법이 없어 (아래 막힌 점) 배포 뒤 결과로 세 값을 확인했다. 틀렸으면 배포가 실패하거나 로그인이 안 됐을 것이고, 다시 넣고 재배포하면 되는 일이라 위험이 작다고 봤다.
- **문서에 URL 은 남기고 비밀번호는 남기지 않는다.** 데모 주소는 저장소를 공개하면 README 와 위키에서 쓸모가 있다. 비밀번호는 지원서에만 적는다. 가이드 4장 7단계 문구를 이렇게 분명히 했다. 대가는 누구나 주소로 들어와 잠든 서버를 깨울 수 있다는 점이다. 새로 가입한 계정은 메일이 없어 로그인할 수 없다.

## 막힌 점과 해결

- **Blueprint 값이 가려져 확인할 수 없음.** Render 는 `sync: false` 칸을 점 12개로 보여 주고, 칸에 포커스를 줘도 값이 나오지 않는다. 사용자가 넣은 값이 맞는지 배포 전에 볼 수 없었다. 배포 결과로 확인했다: 마이그레이션 성공은 `DATABASE_URL` 과 TLS, 세션 쿠키가 붙은 200 은 `SECRET_KEY_BASE` 길이, 사용자 로그인은 데모 비밀번호.
- **로그 화면이 "Build not found".** 서비스의 로그와 이벤트 화면에서 빌드 로그가 보이지 않았다. 이벤트 목록에서 해당 배포 (`/deploys/dep-...`) 화면을 직접 여니 빌드와 배포 로그가 모두 나왔다.
- **브라우저 확인 중 클립보드 경고.** 내장 브라우저가 "합성 입력 중 페이지가 OS 클립보드에 썼다" 고 한 번 알렸다. 원인은 확인 필요. 이후 동작과 결과에는 영향이 없었다.

## Elixir 학습 포인트

- **Docker 안의 release 는 Mix 없이 돈다.** 빌드 단계 이미지에서 `mix release` 로 만든 `_build/prod/rel/tickmark` 만 실행 단계 이미지로 복사한다. 그래서 컨테이너 안에는 `mix ecto.migrate` 가 없고, `bin/migrate` 가 `bin/tickmark eval Tickmark.Release.migrate` 로 마이그레이션을 돈다. `eval` 은 앱을 시작하지 않고 코드만 올리므로 `Ecto.Migrator.with_repo/2` 가 Repo 하나만 잠깐 띄워 마이그레이션하고 내린다. 그 뒤 `bin/server` 가 앱 전체를 시작한다.
- **`::` 바인딩.** Endpoint 의 `ip: {0, 0, 0, 0, 0, 0, 0, 0}` 은 IPv6 의 모든 주소 (`::`) 다. Linux 기본값 (`net.ipv6.bindv6only=0`) 에서는 이 소켓이 IPv4 연결도 받는다. Render 가 포트 10000 을 찾고 요청이 들어온 것으로 이 바인딩이 Render 에서 문제없음을 확인했다. Render 내부 라우터가 IPv4 와 IPv6 중 무엇으로 붙는지는 확인 필요.
- **secret 길이는 첫 요청에서 드러난다.** `Plug.Session.COOKIE` 는 세션 쿠키를 서명할 때 `secret_key_base` 가 64바이트보다 짧으면 예외를 낸다. 부팅만으로는 모르고 세션을 쓰는 첫 요청에서 500 이 난다. 그래서 쿠키가 붙은 `/users/log-in` 200 이 길이 확인이 된다.
- **부팅 시드 Task 의 순서.** 감사 로그의 첫 이벤트 (09:38:47) 는 Endpoint 시작 (09:38:44) 3초 뒤다. 자식 목록에서 Task 가 Endpoint 뒤에 있어서, 서버가 요청을 받기 시작한 다음에 시드가 돈다는 것을 실제 시각으로 볼 수 있다.
