# 안내 (flash) 위치와 사용자 메뉴

- 날짜: 2026-10-28
- 작업자: 메인 세션 (요청: 사용자)
- 관련: [배포 가이드](../planning/2026-10-25-1-배포-가이드-Render-Neon.md) 5.5절과 6장, [병합 뒤 배포 확인 devlog](2026-10-27-2-병합-뒤-배포-확인.md), [화면설계서](../design/2026-10-17-13-화면설계서.html) 3.3 공통 상태

## 목표

사용자 요청: "자동 로그인 안내가 사용자 메뉴를 덮지 않도록 flash 위치를 고치고, 테스트와 문서 갱신 포함해서 precommit 뒤 PR 열어줘".

10-27 배포 확인에서 자동 로그인 안내가 오른쪽 위 사용자 메뉴를 덮었다. 안내 문구는 "검토자로 보려면 로그아웃한 뒤 로그인하세요." 인데, 로그아웃 메뉴를 누르면 첫 클릭이 안내를 닫았다.

## 원인

- 상단 바 (`layouts.ex`) 는 `sticky top-0 z-40 h-12` 다. `position: sticky` 와 `z-index` 가 함께 있으면 새 stacking context 가 생긴다. 사용자 메뉴의 드롭다운은 그 안에 있어서, 드롭다운에 어떤 z 값을 줘도 바깥에서 보면 상단 바 전체가 층 40 에 있다.
- 안내 (`core_components.ex` 의 `flash/1`) 는 `toast toast-top toast-end z-50` 이었다. daisyUI `toast` 는 `position: fixed` 이고 `toast-top` 은 위에서 1rem 이다. 층 50 이 층 40 인 상단 바 전체 위에 그려져 메뉴 단추와 드롭다운을 모두 덮었다.

## 한 일

- `flash/1` 의 class 를 `toast toast-top toast-end top-16 z-30` 으로 바꿨다. 상단 바 (48px) 아래 1rem 인 64px 에서 시작하고, 상단 바보다 낮은 층에 둔다. 왜 이 값인지 HEEx 주석 두 줄을 남겼다.
- `test/tickmark_web/components/layouts_test.exs` 에 테스트 하나를 더했다. 로그인 상태의 셸을 안내와 함께 그린 뒤, `#flash-group` 의 toast 3개 (안내, 연결 끊김 두 개) 가 모두 `top-16` 을 갖고 z 숫자가 `#topbar` 의 z 숫자보다 작은지 본다. 이를 위해 `shell/1` 도우미가 `flash` 를 받도록 바꿨다.
- 테스트 먼저: 코드를 고치기 전에 이 테스트가 실패하는 것을 봤다. `assert "top-16" in classes` 의 right 값이 `["toast", "toast-top", "toast-end", "z-50"]` 였다. 고친 뒤 이 파일 8개 통과.
- 브라우저 확인 (로컬, 아래 "막힌 점" 의 4001 서버):

| 폭 | 안내 | 상단 바 | 메뉴 |

## 결정과 트레이드오프

1. **상단 바 아래, 상단 바보다 낮은 층 (고름)**: 화면설계서 3.3 의 "오른쪽 위" 를 지키면서 한 줄만 바꾼다. 위치 (`top-16`) 만 바꾸면 안내 위로 열리는 드롭다운이 여전히 안내 밑에 깔리고, 층 (`z-30`) 만 바꾸면 안내 윗부분이 상단 바 밑에 가려진다. 그래서 둘 다 바꿨다.
2. **아래쪽 (`toast-bottom`) 은 버림**: S5 의 서명 바 (`sign_bar.ex`, `sticky bottom-0 z-20`) 를 덮는다. 결론 제출과 승인 단추가 있는 곳이라 메뉴를 덮는 것보다 나쁘다. 화면설계서와도 어긋난다.
3. **몇 초 뒤 자동으로 닫기는 버림**: JS hook 과 타이머가 더 들고, hook 은 LiveView 화면에서만 돈다 (홈 같은 컨트롤러 화면은 빠진다). 읽기 전에 사라질 수 있어 접근성 (시간 제한 조절) 문제도 생긴다. 자동 로그인 안내는 검토자로 보는 방법을 알려주는 긴 문장이라 더 그렇다.
4. **상단 바의 층을 올리는 안 (상단 바 z-50, 안내 z-40) 은 버림**: 메뉴는 살지만 안내가 여전히 위에서 1rem 에 떠서 상단 바 밑에 반쯤 가려진다. 위치를 옮겨야 하는 것은 같다.
5. **남는 겹침**: 좁은 화면 (375px) 에서는 안내가 화면 제목 ("감사 대상") 줄을 덮는다. 전에도 안내는 본문 위에 떴고, 누르면 닫히므로 둔다.
6. **테스트를 class 수준으로**: 서버 쪽 테스트는 레이아웃을 계산하지 못한다. 그래서 "안내는 상단 바 아래에서 시작하고, 층은 상단 바보다 낮다" 는 불변식을 class 로 단언하고, 실제 그림은 브라우저에서 봤다. 상단 바의 z 를 숫자로 읽어 비교하므로 누가 상단 바나 안내의 층을 바꾸면 테스트가 알린다.

## 막힌 점과 해결

- 사용자의 개발 서버 (4000) 가 `mix.lock` 변경 (`plug_crypto` 갱신) 뒤 재시작을 요구하는 CompileError 500 을 냈다. 사용자 서버는 건드리지 않고, 4001 포트에 따로 띄워 확인한 뒤 내렸다. 실행 설정 (`.claude/launch.json`) 은 커밋하지 않는다.
- 브라우저 세션에 앞선 점검의 "자동 로그인 끔" 표시가 남아 `/` 자동 로그인이 돌지 않았다. 안내 위치는 어떤 `:info` 안내든 같으므로, `/dev/mailbox` 의 로그인 링크로 로그인해 "로그인했습니다." 안내로 확인했다. 비밀번호는 입력하지 않았다.

## 학습 포인트

- **stacking context**: `position` 이 있고 `z-index` 가 auto 가 아닌 요소는 자기 안의 층을 따로 쌓는다. 안의 요소 z 값은 그 안에서만 비교된다. 드롭다운이 가려지는 문제는 드롭다운의 z 를 올려서는 못 푼다.
- **daisyUI 5 와 Tailwind 4 의 층**: daisyUI 의 컴포넌트 규칙은 `@layer utilities` 안의 중첩 층에 들어간다. CSS 층 규칙상 중첩 층 밖의 규칙이 이기므로, 일반 유틸리티 `top-16` 이 `.toast-top` 의 `top` 을 이긴다. 브라우저에서 계산된 `top` 이 64px 인 것으로 확인했다.
- **Elixir: 문자열 접두사 패턴 매칭**: 테스트의 `z_index/1` 는 `Enum.find_value/2` 에 여러 절을 가진 익명 함수를 넘긴다. `"z-" <> layer` 절이 `z-40` 같은 class 에서 숫자 부분만 묶고, 다른 class 는 `nil` 을 돌려 건너뛴다.
- **함수 컴포넌트 테스트**: `render_component/2` 로 `Layouts.app` 을 감싼 테스트용 함수 컴포넌트를 그리고, `LazyHTML` 로 class 속성을 읽었다. 브라우저 없이 셸 구조를 빠르게 검증한다.
