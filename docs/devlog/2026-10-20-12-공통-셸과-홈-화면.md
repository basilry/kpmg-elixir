## 목표

Phoenix 기본 홈과 헤더를 Tickmark 공통 셸로 교체한다. 로그인 전후 메뉴, 설계 색과 본문 폭, 한국어 오류 안내와 시각 형식을 맞춘다.

## 결정과 트레이드오프

- 테마 플러그인의 두 블록과 속성을 유지하고 설계의 hex 값만 대입했다. oklch 변환을 검토했으나 빌드가 그대로 통과해 변환하지 않았다.
- 테마 스크립트는 `layouts/theme_script.html.heex` 한 곳에서 root와 오류 문서가 재사용한다. 세 문서에 복사하는 대안보다 저장 키와 실패 처리의 차이를 막기 쉽다. 기존 `phx:set-theme`, storage 이벤트와 시스템 테마 변경 흐름을 유지했다.
- 사용자 메뉴는 네이티브 `details`와 daisyUI dropdown으로 구현했다. 별도 JS 상태나 모달을 추가하지 않았다. 좁은 화면에서는 브랜드 텍스트와 이메일을 화면낭독기용으로 유지하고, 감사 대상 이름은 말줄임한다.
- Presence는 계약대로 `%{id, name}` 목록을 받아 최대 4명과 초과 수를 표시한다. 추적과 탭 중복 제거는 메인의 4.4 작업이다.
- 홈에는 `page_title: "분개 테스트"`를 지정했다. root의 default `Tickmark`와 접미사 ` | Tickmark`를 유지하면서 홈 제목이 중복되지 않게 했다.
- 404와 500은 `render_errors`의 `layout: false` 설정에 맞춰 독립 HTML로 만들었다. 500은 전달된 오류 원인을 출력하지 않는다. 비멤버와 없는 감사 대상이 모두 `Engagements.get_engagement!/2`에서 `Ecto.NoResultsError`로 처리되고, 기존 LiveView 테스트도 404를 확인한다.

## 막힌 점과 해결

- 첫 대상 테스트에서는 홈 제목이 `Tickmark | Tickmark`여서 1건이 실패했다. 홈의 페이지 제목을 지정한 뒤 대상 97개가 모두 통과했다.
- 전체 precommit에서는 기존 인증 테스트 3건이 로그인 후 `GET /`의 200 응답을 기대해 실패했다. 새 홈 계약의 응답은 `/engagements`로 302다. F2 소유 파일이므로 수정하지 않았고 코디네이터에게 전달했다.
- 코디네이터 답변: F2가 같은 3곳을 수정 중이며, F1은 현재 결과를 기록하고 마무리한다. 메인이 F2와 합친 뒤 전체 통과를 확인한다. 이 확인 범위 조정에 따라 F1 변경을 커밋한다.

## Elixir 학습 포인트

- 함수 컴포넌트의 `attr` 기본값으로 공통 셸의 입력 계약을 표현한다. `engagement: nil`이면 대상 관련 영역을 그리지 않고 인증 화면과 S1도 같은 셸을 쓴다.
- HEEx의 `:if`, `:for`로 영역과 아바타를 렌더링한다. 표시용 데이터만 받고 기존 LiveView의 도메인 상태와 이벤트 처리에는 손대지 않았다.
- `embed_templates`는 파일을 컴포넌트 함수로 만든다. root와 오류 템플릿이 같은 테마 컴포넌트를 호출할 수 있고, `ErrorHTML`도 404/500 전용 템플릿을 렌더링한다.
- `DateTime.to_iso8601/1`은 기계용 datetime에 남기고 `utc_title/1`은 사람이 읽는 UTC 툴팁에 쓴다. 화면의 KST는 기존 변환을 유지한다.
- 컨트롤러의 redirect는 302이므로 로그인 후 홈을 재요청하는 테스트도 새 흐름을 따라야 한다. 테스트 실패가 화면 자체의 오류인지 이전 동작의 단언인지 구분했다.
